# แผนการหาลูกค้า

> เอกสารประกอบแผน 4.1 (DEV_SPEC §12b M26) · ปรับปรุง 26 ส.ค. 2569
> ตัวเลขฐาน: [business-plan.md](business-plan.md) · จังหวะเวลา: [breakeven-roadmap.md](breakeven-roadmap.md)

**โจทย์:** งบ ฿30,000 ต่อเดือน (฿360,000 ต่อปี) ต้องพาผู้ใช้มาให้ได้ **อย่างน้อย 3,700 คน** เพื่อคุ้มทุน และ **9,700 คน** เพื่อถึงเป้าปีแรก

```
เพดาน CAC ที่ยังคุ้มทุน   = ฿360,000 ÷ 3,700 คน = ฿96 ต่อคน
CAC ที่ต้องทำได้ถึงจะถึงเป้า = ฿360,000 ÷ 9,700 คน = ฿37 ต่อคน
```

ส่วนต่างระหว่างสองตัวเลขนี้คือทั้งแผน: **฿96 ซื้อได้ด้วยเงิน ส่วน ฿37 ซื้อด้วยเงินอย่างเดียวไม่ได้** ต้องมีช่องทางที่ไม่เสียเงินมาช่วยครึ่งหนึ่ง

> ### ตัวเลขที่ทำให้แผนนี้ปลอดภัย
> **ช่องทางที่เสียเงินอย่างเดียว (อินฟลูฯ 3,500 + โฆษณา 1,000 = 4,500 คน) เกินจุดคุ้มทุน 3,700 คนอยู่แล้ว**
> แปลว่าต่อให้ viral loop ไม่ทำงานเลยสักนิด ปีแรกก็ยังไม่ขาดทุน
> ส่วนอีก 5,200 คนจากช่องทางฟรีคือส่วนที่เปลี่ยน "ไม่ขาดทุน" ให้เป็น "กำไร ฿451,000"

## 2. ช่องทางที่เสียเงิน

### 2.1 อินฟลูฯ ในทีม — ข้อได้เปรียบที่คู่แข่งซื้อไม่ได้

`trip-planning-platform-plan.md` §9.4 ระบุไว้เองว่านี่คือ distribution ตั้งต้นที่ทำให้ ROVE ต่างจากคู่แข่ง — มีคนถามหาแพลนอยู่แล้วในคอมเมนต์ ก่อนที่สินค้าจะมีด้วยซ้ำ

**จังหวะการใช้งบ — เทหน้า ไม่เฉลี่ย**

| ช่วง | งบ | เหตุผล |
|---|---:|---|
| เดือน 1 | ฿60,000 | คลิปเปิดตัว · ต้องดังพอให้เกิดคลื่นแรกที่ป้อน viral loop |
| เดือน 2 | ฿40,000 | คลิปตาม + ตอบคอมเมนต์ |
| เดือน 3–12 | ฿26,000/เดือน | คอนเทนต์ต่อเนื่อง + โฆษณา |

**สิ่งที่ต้องมีก่อนคลิปแรกออก:** แพลนสาธารณะตัวอย่าง **10–20 ใบ** พร้อมให้ก๊อป — คนที่กดเข้ามาจากคลิปแล้วเจอห้องว่างเปล่าจะไม่กลับมาอีก และการโฆษณาไปยังสินค้าที่ยังไม่มีของข้างในคือวิธีเผาเงินที่แพงที่สุด

**สิ่งที่คลิปต้องพูด:** ไม่ใช่ "ROVE คืออะไร" แต่คือ **"เลิกเป็นคนที่ต้องจัดทริปให้เพื่อนทั้งกลุ่ม"** — คนที่รู้สึกกับประโยคนี้คือคนที่จะสมัคร

### 2.2 โฆษณาเสียเงิน — ตัวสำรอง ไม่ใช่ตัวหลัก

CAC ในหมวดท่องเที่ยวไทยอยู่ราว ฿80–200 ซึ่ง**สูงกว่าเพดาน ฿96 เกือบตลอด** จึงใช้เป็นตัวเสริมเท่านั้น ไม่ใช่เครื่องยนต์

**เงื่อนไขการใช้:** เปิดเฉพาะเมื่อ CAC พิสูจน์แล้วว่าต่ำกว่า ฿96 จากงบทดสอบก้อนเล็ก (฿5,000) ก่อน · ห้ามเพิ่มงบเพื่อกู้ตัวเลขผู้ใช้ที่ตกในช่วงเดือน 3–5 เพราะนั่นคือรูปทรงปกติของการเปิดตัว ไม่ใช่ความล้มเหลว

## 3. ช่องทางที่ไม่เสียเงิน — สร้างเสร็จแล้วทั้งหมด

> ทั้งสามอย่างนี้**มีอยู่ในโค้ดแล้ว** ไม่ต้องสร้างใหม่ งานคือทำให้มันถูกใช้จริง

### 3.1 ก๊อปแพลนสาธารณะ — เครื่องยนต์หลัก

**กลไก:** เจ้าของทริปเปิดสาธารณะ → คนอื่นเห็นใน `/explore` หรือจากลิงก์ → กด "เที่ยวตามแพลนนี้" → ระบบก๊อปแล้วปรับวัน/จำนวนคน/งบให้อัตโนมัติ (`domain.AdaptPlan` แบบ deterministic) → **คนก๊อปกลายเป็นผู้ใช้ใหม่ทันทีโดยไม่เสียค่าโฆษณา** → เจ้าของแพลนต้นทางได้ 260 แต้ม และได้ 30% ของค่าคอมถ้าคนนั้นจอง

นี่คือจุดที่ผลประโยชน์ของทุกฝ่ายตรงกันพอดี: ผู้ใช้ได้แพลนที่ใช้ได้ทันที เจ้าของแพลนได้แต้มและเงิน ROVE ได้ผู้ใช้ใหม่ฟรีและค่าคอม

**ตัวเลขที่ต้องเฝ้า:** จำนวนก๊อปต่อแพลนสาธารณะหนึ่งใบ · ถ้าต่ำกว่า 0.5 แปลว่าแพลนที่เปิดอยู่ยังไม่น่าตามรอย ปัญหาอยู่ที่คุณภาพแพลน ไม่ใช่ที่การมองเห็น

**สิ่งที่ต้องผลักดัน:** อัตราการเปิดสาธารณะหลังทริปจบ — จุดที่ชวนอยู่บนหน้าบันทึกทริปแล้ว (Decision Log 20 ส.ค. เลือกจุดนี้เพราะทริปที่ไปมาแล้วคือทริปที่คนอื่นอยากตามรอย) แต่ยังไม่เคยวัดว่ามีคนกดกี่ %

### 3.2 ชวนเพื่อน — 150 แต้มต่อคน

**กลไก:** ชวนเพื่อนเข้าห้องทริป → เพื่อนเข้าทริปแรก → ผู้ชวนได้ 150 แต้ม

**ทำไมช่องทางนี้แทบไม่มีต้นทุน:** 150 แต้ม = ฿18.75 เมื่อแลกเป็นส่วนลด (8 แต้ม = ฿1) และ**จ่ายเป็นแต้มไม่ใช่เงินสด** ต้นทุนจริงเกิดก็ต่อเมื่อมีคนเอาแต้มไปแลกจริง

**ข้อได้เปรียบเชิงโครงสร้าง:** ทริปเป็นของกลุ่ม การชวนเพื่อนจึงไม่ใช่ฟีเจอร์ที่ต้องโน้มน้าวให้ใช้ — **มันคือวิธีใช้สินค้า** คนจัดทริปต้องชวนเพื่อนอยู่แล้วไม่ว่าจะมีแต้มหรือไม่ แต้มแค่เร่งให้เร็วขึ้น

**สถานะหลัง M26 (27 ส.ค. 2569):** โครงสร้างพร้อมแล้ว — โค้ดส่วนลดใช้กับ Trip Pass ได้ และอัตรา 8 แต้ม = ฿1 ถูกผูกฐานใหม่เข้ากับคำสัญญานี้โดยตรง (฿299 × 8 = 2,392 แต้ม ≈ ชวนเพื่อน 16 คน — ดู [decision-log.md](decision-log.md))

> **แต่ยังใช้จริงไม่ได้:** โรงมินต์โค้ด (`RedemptionOpen`) ปิดอยู่ตั้งแต่ 26 ส.ค. 2569 รอ Phase 6 และ M26 ปิดขาเดิม (แลกแต้มเป็นร่าง AI) ไปด้วย — ช่วงนี้แต้มจึงยัง**ไม่มีปลายทางที่ใช้ได้จริง** ห้ามโฆษณา "ชวนเพื่อน 16 คน = Trip Pass ฟรี" จนกว่า Phase 6 จะเปิด ไม่งั้นคือการสัญญาสิ่งที่ยังแลกไม่ได้

### 3.3 SEO — ช้าแต่ทบต้น

หน้าแพลนสาธารณะทุกใบมี URL ของตัวเอง (`/p/:slug`) พร้อม OG image และ ISR — ทุกแพลนที่ผู้ใช้เปิดสาธารณะคือหน้าใหม่ที่ Google เก็บได้ **คลังหน้าโตขึ้นเองโดยไม่ต้องเขียนคอนเทนต์เพิ่ม**

คำค้นเป้าหมายคือ long-tail ที่คนค้นตอนกำลังวางแผนจริง: *"แพลนเที่ยวโตเกียว 5 วัน งบ 30000"* ไม่ใช่ *"เที่ยวญี่ปุ่น"* ซึ่งแข่งกับ OTA ที่มีงบมหาศาลไม่ได้

**ข้อจำกัดที่ต้องยอมรับ:** ใช้เวลา 3–6 เดือนกว่าจะเห็นผล จึงนับเป็นผู้ใช้ในครึ่งปีหลังเท่านั้น ไม่ควรคาดหวังในช่วงเปิดตัว

## 5. เฝ้าอะไร ตัดสินใจอย่างไร

| ตัวชี้วัด | เกณฑ์ | ถ้าหลุด |
|---|---|---|
| CAC รวม | < ฿96 | เกินสองเดือนติด → หยุดซื้อสื่อ แก้ viral loop ก่อน |
| สัดส่วน organic | โตขึ้นทุกเดือน · ≥ 50% ที่เดือน 6 | นิ่ง → ปัญหาอยู่ที่สินค้า การตลาดช่วยไม่ได้ |
| ก๊อปต่อแพลนสาธารณะ | > 0.5 | ต่ำกว่า → แพลนยังไม่น่าตามรอย |
| อัตราเปิดสาธารณะหลังทริปจบ | > 20% | ต่ำกว่า → แรงจูงใจยังไม่ชัดพอ |
| สมัครแล้วสร้างทริป | > 40% | ต่ำกว่า → แก้ onboarding **ก่อน**เพิ่มงบโฆษณา |

**กฎข้อเดียวที่ห้ามละเมิด:** ห้ามเพิ่มงบโฆษณาเพื่อกู้ตัวเลข ตราบใดที่อัตราสมัครแล้วสร้างทริปยังต่ำกว่า 40% — การเทเงินใส่ funnel ที่รั่วคือวิธีเผาเงินที่เร็วที่สุดที่มี

## 6. สิ่งที่ยังไม่รู้

1. **CAC จริงของคลิปอินฟลูฯ** — ตัวเลข ฿51 มาจากการประเมิน reach × conversion ที่ยังไม่เคยวัด ทั้งแผนขึ้นกับตัวนี้
2. **จำนวนก๊อปต่อแพลนสาธารณะ** — โค้ดพร้อม แต่ไม่เคยมีทราฟฟิกจริงมาทดสอบ
3. **อัตราการเปิดสาธารณะ** — จุดที่ชวนอยู่บนหน้าบันทึกทริปแล้ว แต่ยังไม่เคยเก็บตัวเลขว่ามีคนกดกี่ %

ทั้งสามข้อวัดได้ตั้งแต่เดือนแรกถ้าติดตั้ง PostHog ให้ครบก่อนเปิดตัว — **ตัวเลขที่ไม่ได้เก็บในเดือนแรกคือตัวเลขที่หายไปตลอดกาล**
